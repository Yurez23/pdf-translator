Приоритеты: сначала качество и полнота перевода, затем максимально крупные
смысловые фрагменты и скорость. Для этой версии не добавляем общий диалог,
накопленную историю переводов или зависимость пакета от перевода предыдущего.
Короткий исходный контекст и заголовки, которые уже передаются, этим решением
не отключаются. Глоссарий пока не разрабатываем и не наполняем.

## 1. Асинхронные запросы: до пяти одновременно — выполнено

- [x] Сделать неблокирующий перевод независимых пакетов с верхним пределом
  **пять одновременно выполняющихся LLM-запросов**, а не обязательными пятью
  OS-потоками. Начать с управляемого ограничителя конкурентности.
- [x] Не ждать перевода предыдущего пакета и не добавлять его в контекст текущего.
  Порядок результатов восстанавливать по исходным ID, не по порядку завершения.
- [x] Сохранить DIP и ручной/автоматический выбор провайдера. Использовать раздельные
  модельные сессии; не разделять между задачами изменяемое состояние SDK/router.
- [x] Координировать общий бюджет попыток, RPM/TPM, retries и все служебные вызовы.
  Пять одновременных запросов не означают пять запросов в секунду или разрешение
  обходить квоты. Сверить локальные резервирования с реальными квотами отдельно.
- [x] Пересмотреть текущие SQLite leases: проба восстановления ограничения не
  должна сериализовать все успешные запросы к одной модели или вынуждать остальных
  работников выбирать более слабую модель только из-за занятой аренды.
- [x] Сериализовать изменения журнала и сохранение принятых результатов; корректно
  обрабатывать отмену, частичный успех, паузы и resume. Не обещать exactly-once
  при сетевом тайм-ауте между ответом и сохранением.
- [x] Проверить офлайн: максимум пять активных генераций, ответы в разном порядке,
  частичные ошибки/отмена, общий лимит, fallback, отсутствие повторной отправки
  сохранённых сегментов и сохранение фактической модели каждого сегмента.

CLI использует `translate_file_async`, `max_concurrency=5` (1–5). Старый
`translate_file` остаётся последовательным API. Лимиты общие и консервативные,
не поднимаются автоматически ради пяти задач. Новая асинхронная реализация
проверена офлайн. Отдельный живой async-тест 20 октября подтвердил пересечение
запросов, но остановился на неверном наборе ID после сохранения 172/250 сегментов.
После блока надёжности свежий strict/async-тест завершился: 250/250 сегментов,
436.582 секунды, 14 API-вызовов, HTTP-повторы и fallback. Ошибок формата ответа
не возникло: response retries в этой живой пробе не потребовались.

Решение 20 октября: **не добавлять fallback для MAX_TOKENS**. Обрезанный пакет
не принимается; нужно пересмотреть размер входа/бюджет ответа. Это не сигнал
исчерпания квоты модели и не отложенная задача по переключению моделей.

### Надёжность ответов без дробления — выполнено

- [x] Strict-схема Gemini с точными обязательными ID, локальная проверка, отдельная
  ревизия. Явный legacy-режим для старых журналов без миграции.
- [x] Ограниченные повторы целого пакета на той же модели при JSON/ID/маркерах,
  пустом тексте и подозрительной длине. Все вызовы через общий бюджет; не fallback.
- [x] После исчерпания — проблемный пакет, продолжение независимых пакетов,
  `incomplete`/код 4, без полного экспорта; сохранение и resume незавершённого.
- [x] Безопасная диагностика категорий, количеств и известных пропущенных ID.
- [x] Офлайн-тесты sync/async, SDK wire format, same-model retry, отсутствие
  дробления/склейки/fallback по ошибке ответа, бюджет, отмена, resume и старый v3.

Дробление проблемного ответа **не реализуется** по решению пользователя.
Прежний входной `BatchTooLarge` остаётся самостоятельной токенной защитой.

## 2. Пакеты по целым подразделам книги — выполнено

- [x] Зафиксировать **16 000 символов** с пробелами как жёсткий верхний кап в CLI
  и API, разрешив только уменьшение (`256–16000`), не превышение ради целого раздела.
- [x] От конца допустимого окна отступать к последней границе законченного
  подраздела. Учитывать вложенные Markdown-заголовки, объединять короткие подразделы;
  не оставлять заголовок/цепочку заголовков отдельно от начала текста.
- [x] Если подраздел слишком длинный: вложенный подраздел, абзац, предложение.
  Не делить слова/маркеры или распознанные предложения по произвольному пробелу.
  Слишком длинное предложение/заголовок либо неделимая пара заголовок/текст —
  явная ошибка, не обрезка и не бесконечный повтор.
- [x] Сохранять подходящие по размеру таблицы, списки и вставки целыми. Большие —
  по строкам/пунктам/абзацам, затем внутренним элементам; выдавать предупреждение
  о разрезанном контейнере и восстанавливать структуру при экспорте. Заголовки
  вставок не влияют на основное оглавление. Детали — в [руководстве](docs/translation.md#смысловые-фрагменты-и-жёсткий-кап).
- [x] Для TXT использовать абзацы/предложения, не угадывать заголовки; сохранить
  предупреждение об отсутствии иерархии.
- [x] Убрать независимый предел 24 сегментов. Учитывать также два символа-разделителя
  между текстовыми элементами пакета.
- [x] Сохранить токенные проверки полного запроса и fallback-моделей. При
  `BatchTooLarge` выбирать смысловые границы без новых ID и одинокого заголовка.
  Увеличить бюджет ответа до `32768`, сохранив отказ от обрезанных ответов;
  это не доказанный коэффициент достаточности или гарантия качества.
- [x] Проверить детерминизм, отсутствие пропусков/дубликатов, защищённые маркеры,
  экспорт и отказ от несовместимого прогресса. Контракт плана версии 3 включает
  политику и границы пакетов; старые журналы не удаляются и молча не мигрируют.
