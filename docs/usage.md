## Требования и установка

Нужны Python 3.12 или новее и PDF с извлекаемым текстовым слоем. Обработка локальная;
после установки зависимостей конвертеру не нужен интернет. Для установки пакетов
доступ к их источнику может потребоваться. Работа со сканами, OCR и веб-интерфейс
не предусмотрены. Эта команда только конвертирует PDF; необязательный перевод
готового текста описан в [отдельном руководстве Gemini](translation.md).

Из корня проекта в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m pdf_translator --help
```

Linux/macOS:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m pdf_translator --help
```

Далее `python` означает интерпретатор этого окружения. Его можно указывать полным
путём, как выше, либо предварительно активировать окружение. После установки
доступна и команда `pdf-translator`. Из корня репозитория модуль можно запускать
без установки самого проекта, если зависимости уже доступны выбранному Python.

## Команда и все параметры

```text
python -m pdf_translator INPUT [--pages PAGES] [--output-dir DIR]
                             [--hyphens {ask,keep,join}] [--overwrite]
                             [--log-dir DIR | --no-log]
```

| Аргумент | Значение по умолчанию | Что делает |
| --- | --- | --- |
| `INPUT` | Обязателен | Путь к исходному PDF. Путь с пробелами заключите в кавычки. |
| `--pages PAGES` | Весь документ | Физические страницы, например `10-25` или `1,3-5`. |
| `--output-dir DIR` | `output` | Каталог результатов, относительно текущего рабочего каталога, если путь не абсолютный. Создаётся при записи. |
| `--hyphens ask` | `ask` | Спрашивать решение для каждого неоднозначного переноса. |
| `--hyphens keep` | — | Не спрашивать; сохранять неоднозначные дефисы. |
| `--hyphens join` | — | Не спрашивать; удалять неоднозначные дефисы. Требует осторожности: настоящий составной термин тоже может быть неоднозначным. |
| `--overwrite` | Выключен | Разрешить замену существующей пары результатов. |
| `--log-dir DIR` | `logs/` корня проекта | Папка технических JSONL-логов; в установленном пакете без checkout — текущей рабочей папки. |
| `--no-log` | Выключен | Отключить технический лог; несовместим с `--log-dir`. |
| `--version` | — | Напечатать версию и завершиться. |
| `-h`, `--help` | — | Напечатать справку и завершиться. |

Отдельных флагов выбора одного формата, имени выходного файла, пароля PDF, OCR,
перевода или запуска аудитора нет. Конфигурационный файл для CLI не требуется.

Конвертация пишет отдельный технический лог, включая ошибки до экспорта и выборы
переносов без самих слов. Он не является журналом для автоматического повторения
ответов. Пределы размера/хранения и диагностика — в [логировании](logging.md).

Примеры:

```sh
python -m pdf_translator book.pdf
python -m pdf_translator book.pdf --pages 10-25 --output-dir output/chapter
python -m pdf_translator "books/My Book.pdf" --pages 1,3-5 --hyphens keep --output-dir output/sample
python -m pdf_translator book.pdf --hyphens ask --output-dir output/reviewed --overwrite
```

### Выбор страниц

Нумерация начинается с 1 и соответствует порядку страниц PDF, а не напечатанным
номерам, римской нумерации предисловия или меткам просмотрщика. Границы диапазонов
включаются. Повторы удаляются, результат упорядочивается по исходному документу:
`--pages 5,1,3-5` даёт страницы 1, 3, 4, 5. Обратные диапазоны, ноль, номера за
пределами PDF и пустая строка недопустимы. Через **невыбранные** страницы
продолжения абзацев не соединяются. Ясное продолжение может пройти через
выбранную пустую страницу; `empty_page` при этом сохраняется. Распознанная форма
может быть отдельной вставкой между половинами абзаца по правилам PDF-03 и не
считается пустой. Если выбрать только её страницу, экспортируется целая вставка.
Выбор сторон с пропуском страницы формы не соединяет их.

Даже для одной страницы программа извлекает и анализирует весь документ:
контекст нужен для колонтитулов, одинаковых уровней заголовков и консервативного
распознавания подписей PDF-04 и системы абзацных отступов PDF-07. Отдельного флага фильтра нет; неуверенные группы
сохраняются, даже если их оформление необычно. В результат
попадают только выбранные страницы; вопросы о переносах и предупреждения от
невыбранных страниц подавляются. Это не режим ускоренного чтения фрагмента:
повреждение на другой странице тоже может помешать прочитать PDF. Словарь для
переносов строится только по выбранному тексту, поэтому выбор диапазона может
изменить автоматические решения о дефисах.

## Граница абзаца после законченного предложения

Законченная фраза может продолжать тот же абзац на соседней странице/в колонке,
если повторяющиеся внутренние границы документа доказывают систему отступов,
у продолжения отступа нет и остальные строгие геометрические условия выполнены.
При слабых/смешанных соглашениях граница остаётся; нового вопроса или режима CLI
нет. [Условия PDF-07](processing.md#законченное-предложение-внутри-продолжающегося-абзаца-pdf-07).

## Неоднозначные переносы

Обычные разрывы строк внутри абзаца превращаются в пробелы. Мягкий перенос
удаляется. Обычный дефис в конце строки обрабатывается по словарю выбранного
текста; если доказательств недостаточно, в режиме `ask` появляется вопрос:

```text
Неоднозначный перенос, страница PDF 11: fort-ress
Контекст:
... a fort-
ress ...
[1] Слить: fortress   [2] Оставить дефис: fort-ress   [Q] Отменить
```

В интерактивном терминале нажмите `1` или `2` без Enter. `Q`, Esc или Ctrl+C
отменяют конвертацию. Неподходящая клавиша вызывает повторный вопрос. Каждый
случай решается отдельно: ответы не запоминаются как пользовательский словарь
и не сохраняются в воспроизводимый журнал переносов. Технический лог фиксирует
лишь `join/keep` и страницу, без слова и контекста. Одно решение применяется к
обоим форматам.

При перенаправлении stdin ответы читаются по одному на строку. Например, в
PowerShell следующий шаблон подходит **только если вы знаете порядок двух вопросов**:

```powershell
@('1', '2') | python -m pdf_translator book.pdf --output-dir output/answered
```

Если ввод закончится до очередного ответа, команда завершится ошибкой, а не
выберет вариант за вас. Для автоматического запуска обычно удобнее явно задать
`--hyphens keep` или `--hyphens join`. Эти режимы разрешают неоднозначности без
`ambiguous_hyphen`; это отличается от Python API без обработчика, где дефис
сохраняется и добавляется предупреждение. Подробнее — [правила обработки](processing.md).

## Файлы результата

Для `books/book.pdf` создаются `<output-dir>/book.md` и `<output-dir>/book.txt`.
Оба — UTF-8, с переводами строк LF. Каждый обычный абзац занимает одну физическую
строку, между блоками — пустая строка. Структурные строки таблиц и списков допустимы.
В Markdown есть заголовки, списки, таблицы и цитатные вставки; TXT содержит тот же
содержательный текст без Markdown-разметки, таблицы разделены табуляцией.
У подтверждённого эпиграфа сохраняются внутренние строки и группы. Записи
соответствий ячеек схемы отображаются отдельными строками Markdown.

Висячие записи без исходного буллита не получают искусственное `-` в Markdown.
Распознанные карточки схем остаются вложенными цитатными блоками; предупреждение
`diagram_layout` означает частичную структуру: уверенные линии экспортируются
как `N1 -- N2 (undirected)`, отдельная стрелка — с `->`, общий стык — `J`,
неразрешённый конец — `U`. Это геометрия, а не условия получения таланта.
В подтверждённых рядах ячеек (Plot Die) используются `C` и явные соответствия.
Перед переводом сверьте связи, пустые ячейки, непривязанные подписи и сомнительные
концы по PDF. Текст каждой карточки/знака сохранён один раз; сгенерированные
ссылки выделены отдельным пояснением. [Поддержка PDF-06](processing.md#связи-и-соответствия-pdf-06).
Подтверждённый заголовок сетки выводится непосредственно перед её строками и
остаётся вне основного оглавления. Группы извлекаемых меток внутри рисунка идут
отдельным блоком. `graphic_text` указывает страницу для проверки визуальных связей.
Проверенные значки представлены метками `[reaction]`, `[2 actions]` и другими
из [списка PDF-01](symbols.md). `unknown_game_symbol` требует сверки исходной
страницы: `[unknown symbol]` не обозначает угаданную стоимость.
Подтверждённая легенда `icon` / `meaning` следует отдельной таблицей вне
карточек и списка связей. Каждый знак и его исходное значение образуют строку.
Таблицы восстанавливаются лишь при достаточных геометрических признаках.
Подтверждённые span, двухуровневые шапки и групповые строки получают составные
заголовки и отдельные секции, одинаковые по отношениям в MD/TXT. Общий выбор
выводится один раз; короткая вертикальная метка повторяется только в своём span.
Неподтверждённая структура остаётся raw-блоком с `complex_table` и страницей.
Отдельных переключателей нет; [правила PDF-02](processing.md#структура-таблиц-pdf-02).

Изображения не экспортируются. Уверенно распознанные подписи к рисункам, имена
художников на полях и колонтитулы исключаются; неуверенные случаи могут остаться.
Подтверждённый горизонтальный ряд одинаковых игровых знаков сохраняется внутри
своей рамки, даже если исходные глифы помечены повёрнутыми. Остальной повёрнутый
текст сохраняется отдельно с `rotated_text` для сверки по PDF.
Сноски, рамочные вставки и структурно подтверждённые формы сохраняются отдельно
от основного текста. Сноска с подтверждённым маркером остаётся сразу после своей
таблицы или правила. Подтверждённая выноска следует за текстом своего раздела.
Обе страницы должны быть выбраны для переноса выноски через границу страницы.
У формы поля и таблицы находятся в одном цитатном контейнере
Markdown; в TXT — подряд с табуляциями в таблицах. В подтверждённой группе
статистики защита и оба её атрибута идут вместе. `[ranks: N]` передаёт число
заполненных кружков отдельно от модификатора. `[blank]` обозначает подтверждённое
пустое поле текущего значения, а записанный ноль остаётся `0`. Если форма
прерывала доказанное продолжение, сначала выводится цельный абзац, затем форма. Иначе она остаётся
между исходными абзацами. Содержимое формы не задаёт заголовки главы; H-номера
могут сдвинуться после исключения её крупных значений. Иерархия выводится по документному контексту PDF-05, но неоднозначное оформление
не гарантирует распознавание семантической вложенности.
Безлинейные и неоднозначные формы могут остаться обычными блоками.
[Правила PDF-03](processing.md#структурные-формы-pdf-03). Подробности
форматов и ролей блоков — в [API](api.md).

Диапазон страниц не включается в имя файла. Запуски для разных глав одной книги
лучше направлять в разные каталоги, иначе имена совпадут. Существующие файлы не
обновляются при изменении программы автоматически. `tmp/audit-current/current.txt`
и `output/example.md` могут принадлежать разным запускам: одинаковая папка проекта
не делает их одной версией. См. [происхождение результатов](quality.md).

При `heading_hierarchy` проверьте оглавление по исходнику: число оформлений не
превращается автоматически в число уровней. `heading_depth` означает глубину свыше
H6: Markdown её уплощает, а Python API сохраняет точный `outline_level`.
TXT остаётся текстовым представлением без кодирования глубины. Выбор одной
страницы сохраняет уровни, установленные по всему документу.

### Защита от перезаписи и сбои записи

Без `--overwrite` наличие хотя бы одного выходного файла останавливает запуск
до конвертации. Проверяются и символические ссылки. При записи используется
исключительное создание, чтобы не затереть файл, возникший между проверками.
Обычная ошибка записи вызывает попытку убрать уже созданные файлы этого запуска.

Все вопросы о переносах завершаются **до** записи результата. Отмена на вопросе
не заменяет старую пару. Исходный файл защищён от совпадения с путём результата.

С `--overwrite` новые тексты сначала готовятся во временных файлах в целевом
каталоге, а затем каждый результат заменяется через `os.replace`. **Пара MD/TXT
не является общей транзакцией**: если замена второго файла не удалась, первый
уже может быть новым. После такой ошибки нельзя считать пару согласованной.
При аварийном завершении процесса возможны остаточные временные или неполные
файлы; перед дальнейшей проверкой установите, какие файлы действительно записаны.

## Сообщения и коды завершения

В stdout идут сообщения `Сохранено: ...`; предупреждения, вопросы и ошибки —
в stderr. Предупреждение содержит код и физические номера страниц. Их полный
список и действия пользователя — в [диагностике](troubleshooting.md).

| Код | Значение |
| --- | --- |
| `0` | Экспорт выполнен, возможно с предупреждениями; также успешные `--help` / `--version`. |
| `1` | Ошибка входного файла, диапазона, конвертации, исчерпанный ввод или ожидаемая ошибка записи. |
| `2` | Ошибка синтаксиса аргументов CLI, например неизвестный флаг или режим переносов. |
| `130` | Отмена пользователем. |

Код `0` означает завершение операции, а не независимую оценку качества. Неожиданная
ошибка программы может сопровождаться traceback; сохраните его для диагностики.
