# Технические логи

Коды предупреждений конвертации `graphic_text`, `diagram_layout` и
`unknown_game_symbol` входят в безопасный allowlist:
в событии сохраняются категория и страницы, не содержимое графического элемента.
Схема событий остаётся v1; это не диагностика каждого пропущенного встроенного знака.
Для `unknown_game_symbol` записываются только код и физические страницы.
Исходные символы, CID, названия/программы шрифтов, контуры, метки и данные
`Word.glyphs` в лог не попадают. [Пределы обнаружения](symbols.md#диагностика-и-пределы)
не позволяют считать отсутствие предупреждения гарантией полноты.

Известное ограничение живого strict/async-теста 20 октября 2026 года: частые
cache/probe-wait события вытеснили начало запуска при ротации; остались файлы
000007–000009. Retention ограничивает диск, но не гарантирует полную трассу
длительного запуска. Итоговая длительность сохранилась в run.finished, число
вызовов — в журнале. Отсутствующие ранние тайминги восстановить нельзя;
снижение шумности/сохранение полной диагностики требует отдельного изменения.

[Все разделы](README.md) · [Перевод](translation.md) · [Разработка](development.md)

Логирование покрывает конвертацию PDF и отдельный этап перевода. Это локальные
структурированные события, не перехват stdout/stderr и не запись содержимого
документа. Используются только средства стандартной библиотеки; PDF-конвертация
остаётся полностью локальной, корневые восемь имён API не меняются.

## Где лежат файлы и как отключить

Обычная конвертация и перевод с `--send` автоматически создают технический лог
в `logs/` корня checkout. В установленном пакете без checkout используется
`logs/` текущей рабочей папки. Имя содержит UTC-время, случайный идентификатор
группы файлов и номер части: `run-YYYYMMDDTHHMMSSZ-<uuid>-000001.jsonl`.
Путь первой части выводится в stderr; при ротации номер части увеличивается.

Оба CLI поддерживают:

| Параметр | Действие |
| --- | --- |
| `--log-dir PATH` | Выбрать отдельную папку технических логов. Явный флаг разрешает лог и для локального плана перевода. |
| `--no-log` | Не создавать технический лог. Несовместим с `--log-dir`. |

```powershell
python -m pdf_translator example.pdf --hyphens keep
python -m pdf_translator book.pdf --log-dir logs/conversion
python -m pdf_translator.translation output/example.md --send --log-dir logs/translation
python -m pdf_translator.translation output/example.md --no-log
```

Без `--send` **и без явного `--log-dir`** план перевода по-прежнему не пишет файлов,
не читает ключ и не обращается к сети/SQLite. Справка, версия и ошибки разбора
аргументов возникают до настройки логов и не создают их. Начало записи после
разбора аргументов означает, что ошибки бизнес-проверок и отсутствующий исходник
уже могут иметь отдельный технический лог.

`logs/`, `output/` и `tmp/` исключены из Git. Для произвольного `--log-dir` вне этих
папок пользователь сам сохраняет ignore-границы; код не редактирует `.gitignore`
автоматически. Логи не добавляются в офлайн-HTML документации.

## Что записывается

Каждая строка — самостоятельный UTF-8 JSON-объект (`schema_version=1`). У всех
событий есть `timestamp` в UTC, случайный `run_id`, монотонный в рамках запуска
`sequence`, `level` и `event`. ID группы файлов в имени не обязан совпадать с
`run_id` внутри событий; все части одного запуска содержат один `run_id`.

Длительность в `duration_ms` измеряется `time.perf_counter`, а не разностью
календарных часов. Метки UTC нужны для сопоставления с внешними событиями; при
корректировке системных часов порядок определяет `sequence`, не сортировка UTC.
События `.started` и `.finished` соединяются по `span_id`; `parent_span_id`
показывает вложенность. Идентификаторы не содержат имени книги или её текста.

| Область | События и данные |
| --- | --- |
| Запуск | `run.started/finished`: команда, итог, код CLI, общее время основной операции после настройки лога. |
| Конвертация | Открытие PDF, общее/выбранное число страниц, извлечение и вёрстка каждой страницы, фильтры имён/подписей/полей, буквицы, словарь, заголовки, продолжения, рендеринг, количество слов/таблиц/блоков. |
| Выбор переноса | Время callback и решение `join/keep`, номер страницы; само слово, варианты и контекст не пишутся. |
| План перевода | Разбор, смысловая нарезка, число элементов/сегментов/пакетов и размер исходника в байтах, без текста или имени файла. |
| Пакет | `translation.batch.*`, проверка, сохранение, дробление, возобновление и итог. `batch_id` стабилен: `b000001`; после токенного деления — `.1`/`.2`. Сегментные ID и формат журнала не меняются. |
| Внешняя попытка | `api.request.started/finished`: уникальный `request_id`, вид вызова, модель Gemini/auto, номер попытки, предел попыток, тайм-аут, токенный резерв, длительность, результат и доступный HTTP-код ошибки. |
| Ограничители/повторы | `api.wait.*`, `api.retry`, `api.retry_wait.*`: причина/запрошенная задержка и фактическое время ожидания отдельно от запроса. |
| Auto/fallback | Размер каталога, выбор/пропуск модели, причина fallback или паузы, фактическая модель ответа. Ключевой namespace не записывается. |
| Хранилища | Время операций журнала прогресса/экспорта, получение/освобождение блокировки, SQLite-транзакции без пути БД, SQL, параметров или содержимого. |
| Gemini usage | `provider.input_count`, `provider.usage`, `provider.finish_reason`: числа входа, выхода, thinking, общего расхода и cache, если SDK действительно их вернул; безопасная категория завершения. |

Для стороннего переводчика виды внешних вызовов по умолчанию `external`; ни SDK,
ни Gemini-промпт не навязываются. В модели технических событий неизвестные ID
движков не сохраняются как произвольные строки: `model` допускает только auto
и валидные публичные Gemini-ID, `provider` — Gemini/auto либо `external`.

`api.request` измеряет одну внешнюю попытку вместе с локальной обработкой ответа
адаптером. Ожидание минутного ограничителя, backoff, запись прогресса перед
попыткой и финальный экспорт не входят в этот интервал. Пакет и весь запуск
дополнительно имеют собственные длительности, включающие их вложенную работу.
Номер `attempt` считается внутри одного вызова executor: fallback на другую модель
создаёт новую попытку с другим `request_id`, но прежним `batch_id`.

Для модельных HTTP `503/504` после обычных повторов auto пишет
`routing.fallback` с `reason=unavailable`, фактическим `status_code` и
`delay_seconds` до новой проверки этой модели (не меньше 300 секунд).
Это не обязательная пауза всего перевода: следующая модель проверяется сразу,
если общий бюджет и минутный ограничитель позволяют. Сеть и другие `5xx`
автоматически не превращаются в такие события. Схема событий остаётся версии 1.

`token_reservation` — защитный локальный резерв, не реальное потребление или цена.
SDK-счётчики — отдельные поля; неизвестные значения отсутствуют, известный ноль
остаётся нулём. Число из `countTokens` не подменяет фактический output/thinking.
Успешный вызов не получает выдуманный HTTP-код, если адаптер его не предоставил.

## Уровни и предупреждения

- `INFO`: этапы, успешные попытки, выбор модели, сохранение, штатные ожидания.
- `WARNING`: эвристические предупреждения, запланированный повтор/fallback,
  приостановка по бюджету/доступности и отмена пользователем.
- `ERROR`: неуспешная операция или внешняя попытка. Ошибочная попытка может иметь
  последующий успешный повтор; это не обязательно провал всего запуска.

Безопасный `error_code` отличает квоту, бюджет, вход/валидацию, файловый сбой,
HTTP-провайдера, клиентский `network_timeout`, транспорт и неожиданный сбой SDK.
Он определяется общим контрактом `DiagnosticError` и реальными типами
отмены/файловых ошибок, не названием класса или текстом исключения. HTTP 504 остаётся отдельным `status_code=504`,
а не автоматически объявляется клиентским тайм-аутом.

Для перевода пишется категория (`numbers_changed`, `unchanged_text`,
`container_split`, `txt_structure`, `literal_preserved`, `preview`, `unspecified`)
и доступный ID элемента. Для конвертации сохраняются её исходный код и номера
страниц (до 100 номеров в одном событии), но не сообщение с текстом книги.
Повтор одного переводческого предупреждения при повторном планировании CLI
подавляется в пределах запуска. Разные предупреждения конвертера не объединяются
лишь потому, что совпали код и страница: их дедупликация остаётся за конвертером.

Терминальные сообщения и `ConversionResult.warnings` сохранены.
`TranslationResult.warnings` теперь содержит типизированные `TranslationWarning`;
категория передаётся явно, текст не разбирается. Для прежних строк используйте
`tuple(map(str, result.warnings))`; подробности — [переход API](solid.md#изменения-python-api). Классификация для лога не исправляет ложное срабатывание `1,000 → 1000`
и не превращает эвристику в доказанную ошибку.

## Безопасность и ограничение размера

Формируется собственный поток событий через `EventSink`, не общий root logger.
Логгеры Google/httpx/pdfminer не перехватываются. Действует allowlist полей/типов,
а не попытка вычистить секреты из произвольной строки. Не записываются:

- API-ключи, env, заголовки, URL, namespace ключа/проекта и аргументы командной строки;
- имена/пути исходников, исходный текст, переводы, контекст, глоссарий и промпты;
- строки исключений, traceback, сырые запросы, ответы и произвольные progress labels.

Имена событий и технические категории задаёт доверенный код. Это не sandbox для
злонамеренного адаптера/пользовательского sink; сторонние реализации обязаны
соблюдать тот же контракт. Технические метаданные и модель тоже могут быть
чувствительными: проверяйте файлы перед публикацией. Логи локальные, не шифруются
и не отправляются разработчику автоматически.

Одна часть — не более 1 МиБ, остаются максимум три части текущего запуска.
При ротации более старые части удаляются. При открытии/ротации удаляются только
обычные файлы с точным собственным шаблоном имени: сначала старше 14 дней, затем
самые старые неактивные к целевому пределу 60 файлов в папке. Активные файлы
защищены OS-блокировкой; их не удаляют ради лимита. Поэтому при большом числе
активных запусков/ошибках доступа общий предел папки мягкий. Это скользящая
диагностика, не бессрочный аудит: начало большого запуска может уйти при ротации.
Чужие файлы, символьные/жёсткие ссылки не очищаются; log-dir через symlink/junction
отклоняется. Удалённые ротацией/retention записи автоматически не восстанавливаются.

Ошибка открытия папки/файла останавливает CLI до основной операции: выбрать другой
`--log-dir` или явно `--no-log`. Если sink ломается после открытия, запись этого
запуска отключается, в stderr один раз выводится `logging_unavailable`, основная
операция продолжается. Отказ логгера не становится повтором перевода или повреждением
его прогресса. Отмена/ошибка основной операции записывается и повторно выбрасывается,
а не скрывается логом. Принудительное убийство процесса/сбой питания могут оставить
старт без завершения или неполную последнюю строку; fsync на каждом событии нет.

## Как посмотреть время генераций

После завершения запуска в PowerShell:

```powershell
Get-ChildItem .\logs\*.jsonl | Get-Content |
    ForEach-Object { $_ | ConvertFrom-Json } |
    Where-Object { $_.event -eq 'api.request.finished' -and $_.request_kind -eq 'generation' } |
    Select-Object timestamp, run_id, batch_id, model, attempt, status, duration_ms, status_code
```

При выборе нескольких запусков группируйте по `run_id`, повторы — по
`batch_id`/модели и `request_id`. Сравнивайте максимумы и распределение, не только
среднее. Старый живой тест до внедрения логов задним числом ими не дополняется;
для новых живых измерений нужна отдельная команда пользователя.

## Подключение из Python

Без явной настройки библиотечные функции ничего дополнительно не записывают.
Сам `log_run` принимает узкий `EventSink`; конкретным файлом владеет вызывающий код:

```python
from pdf_translator import convert_pdf
from pdf_translator.logging_setup import JsonlSink
from pdf_translator.telemetry import log_run

with JsonlSink("logs") as sink:
    with log_run(sink, command="conversion"):
        result = convert_pdf("example.pdf")
```

Для `plan_translation` / `translate_file` / `translate_file_async` действует тот же контекст. Сеть по-прежнему
требует явного разрешения; логирование не подключает и не выбирает провайдера.
`EventSink.write(record: dict)` может сохранять события в тестовую память или другую
систему. Настройки логов не входят в fingerprint и не меняют журнал версии 3,
совместимость планов, identity адаптера или выходные тексты.

Контекст хранится в `ContextVar`: async-задачи получают его обычным способом,
для нового OS-потока надо явно передать отдельный `contextvars.copy_context()`.
Общий sink сериализует запись, а счётчик событий и дедупликация защищены lock.
Разные CLI-процессы получают разные файлы, не общий append-файл. CLI перевода
использует async-задачи: события разных пакетов перемежаются, а не образуют
последовательные группы. Для сопоставления используйте run_id/batch_id/request_id,
не соседство строк. Событие `translation.concurrency` содержит `max_concurrency`;
`routing.probe_wait` измеряет ожидание занятой пробы восстановления модели.
Схема событий v1 сохранена. Сумма длительностей пересекающихся запросов/ожиданий
может превышать длительность запуска: это не ошибка измерения. Журнал прогресса
пишется одним event loop, не произвольными OS-потоками.

## Диагностика восстановления ответа

`translation.response.started/finished` отмечает полный цикл получения и
валидации, а `response_attempt` отличает его от HTTP `attempt`.
`translation.response_rejected` содержит `response_issue`, `expected_count`,
известный `received_count`, а при несовпадении ID — `missing_count` и
`unexpected_count`. Неразобранный JSON не означает «получено 0»: неизвестные
значения отсутствуют. `translation.response_missing` содержит только известный
исходный segment_id (до 100 на отклонение), не произвольные ID от модели.
`translation.response_retry` отмечает следующую попытку той же модели;
`translation.batch_failed` — исчерпание повторов и изоляцию пакета.

Категории: `invalid_json`, `response_structure`, `duplicate_id`, `id_mismatch`,
`invalid_text`, `protected_markers`, `response_length`. Error-коды
`response_validation` / `response_exhausted` не заменяют HTTP-коды или safety.
При неполном переводе run/summary имеют `status="incomplete"` (CLI exit 4),
а не success; span incomplete имеет WARNING. Схема событий остаётся v1 с
расширенным allowlist. Сырые ответы, тексты и посторонние строковые ID не пишутся
в лог; безопасные метаданные проблемных пакетов хранятся отдельно в JSON-журнале.
