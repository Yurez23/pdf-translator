## Все коды предупреждений

В CLI предупреждения идут в stderr с физическими номерами страниц; в Python
доступны в `result.warnings`. Они не делают успешный экспорт ошибкой: CLI может
вернуть `0` с предупреждениями. Поля модели и подавление дублей описаны в [API](api.md).

| Код | Когда возникает и что происходит | Что проверить |
| --- | --- | --- |
| `empty_page` | После извлечения/начальной фильтрации на выбранной странице нет слов. Если другие выбранные страницы содержат текст, конвертация продолжается. | Реально пустая ли страница, нет ли только рисунка/скана. Намеренно пустую страницу можно принять; текст изображения не будет восстановлен. |
| `insert_continuation` | Вероятное незавершённое продолжение через подтверждённую форму не склеено из-за геометрического конфликта; одно предупреждение на цепочку страниц. | Сверить границу абзаца и маршрут колонок по источнику. Текст и форма сохраняются отдельно; невыбранные страницы, законченные абзацы и несовместимые блоки сами по себе не вызывают этот код. |
| `unmapped_glyph` | В извлечённом тексте встречаются U+FFFD или `(cid:N)`. Содержимое сохраняется, но кодировка символов ненадёжна. | Сравнить специальные символы с PDF. Другая текстовая копия исходника может помочь; программа не исправляет карту шрифта. |
| `unknown_game_symbol` | Обнаружен неопознанный глиф известного игрового семейства или характерный неполный/конфликтующий вектор. Вставлен `[unknown symbol]`. | Сверить указанную физическую страницу. Значение/количество не угадывается; исходный текстовый глиф доступен в `Word.glyphs`. [Поддержанные представления и пределы](symbols.md). |
| `table_detection` | Детектор таблиц получил обрабатываемую ошибку. Неразобранный текст остаётся для обычной сборки блоков. | Не потерялись ли ячейки и связи строк/столбцов. Это не гарантия корректного табличного порядка в прозе. |
| `ambiguous_hyphen` | В API без resolver обе формы слова не подтверждены выбранным текстом. Дефис сохранён. | Сверить слово; при разрешённой новой конвертации передать callback или выбрать CLI `ask`. CLI keep/join/ask разрешают такие случаи через resolver и не создают это предупреждение. |
| `complex_table` | Геометрия/шапка/span не подтверждены общими правилами PDF-02. Сохраняется отдельный `raw` с ролью `complex_table`; при доступных словах — физические строки без повторной выдачи пересекающихся ячеек. | Полноту текста, значения и связи по исходнику. `None` сам по себе не доказывает span. Raw и его разделители не обещают табличную структуру. |
| `rotated_text` | Слова с `upright=False`, оставшиеся после фильтра имён и выделения подтверждённых рядов игровых знаков. Они сохранены в `raw/rotated` в конце страницы. | Сверьте порядок, читаемость и связь с окружающим содержимым. Предупреждение может относиться к полезному тексту или игровым знакам. См. [проверку PDF-08](quality.md#pdf-08-проверка-постановки). |
| `heading_depth` | Установленная глубина превышает 6; Markdown ограничен H6, точная глубина остаётся в `Block.outline_level`. | Markdown теряет различие глубоких уровней. Сверить структуру; семь оформлений сами по себе не вызывают этот код. |
| `heading_hierarchy` | Для части выбранных заголовков нет подтверждённого отношения вложенности; оставлен неглубокий fallback без отдельного уровня на каждый размер. | Проверить ближайшие разделы по PDF. Предупреждение означает неопределённость, а не доказанный дефект содержания. |
| `graphic_text` | Надпись или глиф графического элемента сохранены отдельно вне оглавления. Несколько меток одного рисунка могут образовать группу `graphic_labels`. | Сверьте визуальные связи по PDF. Поддержаны метки PDF-01 и отдельные соответствия PDF-06. Нераспознанный рисунок может остаться без предупреждения. |
| `diagram_layout` | Карточки сохранены; PDF-06 добавляет подтверждённые геометрические связи, сохраняя частичный статус. | Сверить N/J/U-ссылки, направление, баннеры и непривязанные подписи по PDF. Линия не означает prerequisite или AND/OR; отсутствие ребра не доказывает отсутствия связи. |

Если **все выбранные страницы** не содержат извлекаемых слов, результат не
возвращается: возникает `ConversionError`, а не успешный пустой экспорт с
`empty_page`. Отдельных кодов для каждой сомнительной подписи, каждой неверной
границы абзаца или каждой строки без рамки нет. Ноль предупреждений не доказывает
качество результата.

## Ожидаемые ошибки

Сообщения могут включать конкретный путь или тип ошибки; таблица описывает
условия, а не контракт дословных строк для машинного разбора.

| Ситуация | Поведение | Действие пользователя |
| --- | --- | --- |
| Файл отсутствует или это каталог | Ошибка конвертации, CLI `1`. | Проверить путь и текущую папку. Пути с пробелами заключить в кавычки. |
| Повреждённый/неподдерживаемый PDF | Понятная ошибка чтения, CLI `1`. | Проверить открытие в просмотрщике и наличие корректной исходной копии. Ошибка может быть и на невыбранной странице. |
| Шифрование или пароль | Отклоняется; аргумента пароля нет. | Если у вас есть доступная незашифрованная копия, использовать её. Даже открывающийся без запроса пароля шифрованный файл отклоняется. |
| Нет страниц, нет текста в выборе, всё удалено до экспорта | Ошибка, не пара пустых файлов. | Проверить диапазон, текстовый слой и структуру исходника. |
| Неверный диапазон (`0`, `5-3`, номер за границей, пустая строка) | `ConversionError`, CLI `1`. | Использовать физические номера 1-based, например `1,3-5`. |
| Неизвестный флаг или `--hyphens` с другим значением | Argparse выводит справку об ошибке, CLI `2`. | Проверить `--help`. |
| Уже существует MD или TXT, в том числе ссылка | Без `--overwrite` остановка до конвертации, CLI `1`. | Выбрать новый каталог; добавлять `--overwrite` только при намеренной замене. |
| Результат совпадает с исходным файлом по пути | CLI отказывается записывать, даже с `--overwrite`. | Выбрать другую папку результата. |
| Нет ответа на неоднозначный перенос, stdin закончился | Ошибка до записи, CLI `1`. | Запустить в терминале, подать все ответы или явно выбрать keep/join. |
| Пользователь нажал Q/Esc/Ctrl+C | Отмена, CLI `130`. | При необходимости запустить снова; решения не сохранены автоматически. |
| Нет прав/места или другая ошибка записи | CLI `1`. | Проверить каталог и согласованность пары. С `--overwrite` первый файл уже мог замениться до сбоя второго. |
| Callback вернул не bool или выбросил исключение | `TypeError` / исходное исключение в Python API. | Исправить вызывающий код; это не обычная ошибка исходного PDF. |

Установка пакета и системное окружение — отдельный слой. `ModuleNotFoundError`
для `pdfplumber` обычно означает не то окружение или неустановленные зависимости;
для `pdf_translator` — запуск вне репозитория без установки пакета. Используйте
тот же Python для `-m pip install -e .` и запуска. Синтаксическая ошибка на
`type BBox = ...` указывает, в частности, на Python ниже версии 3.12.
Для запуска тестов нужен extra `dev`, а не только рабочая зависимость.

## Частые вопросы по качеству

### Осталось `fort-ress`, хотя другие слова склеились

Это может быть ожидаемой осторожностью, а не пропущенным разрывом строки:
слитная форма других слов была подтверждена выбранным текстом, а `fortress` — нет.
Мягкий перенос также обрабатывается иначе, чем обычный ASCII-дефис. Смотрите
режим `--hyphens`, callback/предупреждения и исходное слово. CLI `ask` позволяет
принять решение отдельно для каждого случая; общего сохранённого словаря нет.

### Подпись к рисунку осталась в предложении

Фильтр требует нескольких признаков сразу. Подпись может совпадать со стилем
прозы, быть слишком длинной, лежать далеко от растрового изображения или относиться
к чисто векторному рисунку. Неуверенный текст сохраняется для защиты от потерь.
Для диагностики нужны страница, её визуальный вид, слова/координаты/стили и блок
результата. Удаление всех слов внутри картинки или всех коротких строк небезопасно.
Слитый с полностраничным фоном рисунок не становится обычным изображением-кандидатом.
PDF-04 добавляет отдельную строгую проверку компактных крупных многострочных
подписей: геометрия, завершение фразы, отличие шрифта и цвета, проза и защищённые
стили всего документа. При слабых признаках группа остаётся целиком. Одиночные
строки, произвольные цитаты и подписи без документного контекста не обещаны.
См. [правило PDF-04](processing.md#подписи-на-полностраничном-фоне-pdf-04).
Отдельного предупреждения о сохранённой неоднозначной подписи нет.

### Одна вставка выглядит как несколько цитат

У распознанной заполненной рамки должен быть один `aside` с `children`; то же
относится к многопараграфной цитате, контейнеру карточек схемы и форме
`aside/form_insert`. В Markdown
пустые строки внутри неё содержат `>`. Проверьте, что смотрите свежий файл и что
сама рамка обнаружена. Простая обводка без заливки или нестандартное оформление
могут не распознаться. Другие нераспознанные вставки без рамок не обязаны получить
дочернюю структуру. Формы PDF-03 требуют выраженной геометрии полей; одна рамка,
несколько коротких надписей или обычная табличная сетка недостаточны. Распознанная
форма сохраняет поля и настоящие таблицы вместе, включая подпись при достаточных
признаках. Её значения не должны создавать основные заголовки главы.

Ранги и пустые значения выводятся явно, когда подтверждены исходные кружки и
границы полей. Неясная отметка или неполная сетка оставляют обычный текст формы.
Проверка пустоты учитывает текст и локальные векторные отметки. В поле с
растровыми отметками или штрихами за его пределами нужна сверка с PDF.

### Продолжение на следующей странице не соединилось

Склейка требует согласованной геометрии, шрифта, длины последней строки и признака
продолжения. Кавычка не мешает, но произвольное заглавное начало не является
достаточным признаком: нужно, например, закрытие скобки с прошлой страницы.
Невыбранная страница, отступ нового абзаца или нераспознанный специальный блок могут запрещать
склейку. См. точные условия в [алгоритме](processing.md).

После законченного предложения PDF-07 допускает склейку только при многократно
подтверждённой документной системе отступов, полной последней строке и отсутствии
нового отступа/структурного барьера. Заглавная буква сама по себе не запрещает
и не разрешает её. При короткой строке, слабых или противоречивых образцах
лишняя граница сохраняется без отдельного предупреждения. Совпадения шрифта
и выравнивания недостаточно; [точное правило](processing.md#законченное-предложение-внутри-продолжающегося-абзаца-pdf-07)
не является универсальным восстановлением авторских абзацев.

Через `form_insert` склеиваются только ближайшие обычные абзацы при доказанном
продолжении и однозначном маршруте. Между ними должны быть выбраны все страницы;
смешанная страница не пропускается целиком. При успехе цельный абзац выводится
перед формой, при отказе сохраняется физический порядок. Форма не становится
пустой страницей. Геометрическая неопределённость вероятного продолжения может
дать `insert_continuation`; восстановить смысл произвольного разрыва алгоритм
не обещает.

### Разные шрифты заголовков получили один уровень

Разные размеры, семейства и цвета не означают разные глубины. PDF-05 использует
повторяющиеся композиции, границы, нумерацию и отношения разделов. Названия схем,
форм, таблиц и вставок исключаются из основного оглавления по контексту вхождения.
Неподтверждённые отношения остаются неглубокими с `heading_hierarchy`.
`heading_depth` сохраняется при установленной глубине свыше H6; точное значение
доступно в `outline_level`. Не считать отсутствие предупреждения доказательством
универсального понимания структуры. [Правила и ограничения](processing.md#заголовки-по-всему-документу).

### Почему конвертация пары страниц всё равно медленная

Для контекста извлекается и собирается весь PDF. Это ожидаемое свойство текущей
реализации, не обещанный быстрый режим диапазона. Автоматическое кэширование,
параллельная обработка страниц и постоянный индекс не реализованы.

## Перевод: auto, квоты и SQLite

`--model auto` получает свежий каталог и пропускает модели с ещё действующим
ограничением в `model-availability.sqlite3` в корне проекта. Отсутствие вызова
лучшей модели может быть следствием этого кэша, а не ошибки сортировки.
При известном изменении доступа можно явно указать `--reset-availability` или
`--ignore-availability-cache` вместе с `--send`. Готовый журнал не требует
подготовки адаптера и не сбрасывает кэш; подробности — в [переводе](translation.md).

Код `3` означает сохранённую паузу: бюджет попыток или временно закончились
модели/общая квота. Ключ/параметры/фильтр/плохой JSON не маскируются fallback.
Ошибки JSON/ID/маркеров получают один повтор целого пакета на той же модели
(`--max-response-retries`, 0–5). Если ошибка повторяется, остальные пакеты
продолжаются; результат — incomplete, CLI код **4**, без полного MD/TXT.
В выводе перечислены проблемные пакеты, в логе — категории и безопасные
количества/известные пропущенные ID. Повторы не дробят пакет и не склеивают
сомнительные части. Продолжение — `--resume`, только для непринятых сегментов.

Новый `--gemini-response-format strict` меняет протокол и ревизию. Для прежнего
Gemini-журнала используйте `--gemini-response-format legacy --resume` с теми же
смысловыми настройками; не удаляйте прогресс и не исправляйте fingerprint вручную.
Legacy сохраняет прежний промпт/схему и получает новые повторы/изоляцию. Это
явный выбор, не автоматическая миграция. Подробнее —
[блок надёжности](translation.md#надёжность-ответов-повторы-без-дробления).
В режиме auto HTTP `503/504` выбранной модели после штатных повторов переключают
тот же пакет на следующую модель. Неисправная модель отмечается как `unavailable`
на 5 минут либо дольше по Retry-After. Это не суточная квота. Если недоступны все
кандидаты, сохраняется пауза с кодом `3`; продолжение — через `--resume`.
Клиентские сетевые тайм-ауты, другие `5xx` и сбой самого каталога не считаются
основанием для такого переключения. При явном `--model gemini-...` fallback нет.
Ошибка SQLite требует проверить путь, права и другие процессы; чужая, повреждённая
или неизвестная версия базы автоматически не перезаписывается. Кэш доступности
не заменяет журнал книги и не содержит API-ключей или текста.

Для нескольких ключей одного проекта задайте один `--project-id` /
`GEMINI_PROJECT_ID`. Без этого кэш автоматически разделяется по хешу ключа.
Реальная доступность зависит от сервера: локальные сроки не обещают восстановление
квоты точно в указанную секунду. Поля `segment_models` и `catalog` в журнале
помогают узнать, чем действительно переведены принятые сегменты.

### Ошибки смыслового разбиения

HTTP 504 при генерации означает, что запрос не завершился в установленный срок.
После неуспешной живой пробы при 120 секундах стандартный `--timeout-seconds`
увеличен до 300 (допустимо 1–300); SDK передаёт срок и клиенту, и серверу.
Это не гарантия успешной генерации. Тайм-аут применяется к каждой попытке,
поэтому с двумя повторами один запрос может занять около 15 минут плюс задержки.
Изменение тайм-аута не меняет fingerprint: совместимый журнал можно продолжить
с новым сроком, не переводя заново принятые сегменты. Повторная живая проба всей
контрольной главы при 300 секундах завершилась успешно, но это не гарантия для
других запусков. В текущем auto сохраняющаяся HTTP 504 после повторов приводит
к fallback; простое изменение срока не превращает клиентский сетевой тайм-аут
в модельный сигнал недоступности.

`max_chunk_chars` по умолчанию 16000, выше этого значения установить нельзя.
Превышение длины одного предложения/заголовка либо неделимой пары заголовок/текст
вызывает ошибку до отправки. При уменьшенном капе можно увеличить его до 16000;
иначе нужно вручную подготовить исходный элемент. Текст не обрезается по слову.
Разделитель предложений — английская эвристика, не универсальный NLP-анализатор.

Предупреждение `u…: контейнер table/list/quote … разделён между пакетами` означает
разбиение слишком большого контейнера (либо нехватку места вместе с заголовком),
не потерю структуры экспорта. Подробнее — [политика фрагментов](translation.md#смысловые-фрагменты-и-жёсткий-кап).

Контракт планирования теперь версии 3. Прежний журнал с контрактом 2 нельзя
возобновить даже с `--max-chunk-chars 4000`: выберите новую папку результата,
не удаляйте старый прогресс. Ошибка входных токенов может потребовать уменьшения
капа/контекста/глоссария; символный кап не отменяет лимитов конкретной модели.
Ответный запас по умолчанию теперь 32768 (прежде 16384), но это также не
гарантирует полноту: `MAX_TOKENS` по-прежнему не принимается и не вызывает fallback.
Нужно пересмотреть размер пакета или ответный бюджет, а не считать это
исчерпанной квотой. Локальный
`tokens_per_minute` по умолчанию 50000 согласован с новым бюджетом; при явном
меньшем значении контроллер может отказать ещё до генерации. Старые журналы
с бюджетом 16384 требуют явного `--max-output-tokens 16384` при `--resume`;
для нового бюджета выбирайте новый каталог, не удаляйте сохранённый прогресс.

CLI перевода использует до пяти асинхронных работников, но общий локальный
резерв 50000 TPM часто разрешает только одну новую генерацию за минуту.
Это не зависание и не означает, что пять работников получили отдельные квоты.
`--max-concurrency 1` уменьшает конкурентность, не меняя совместимость журнала.
При ошибке CLI сначала сохраняет корректные ответы уже отправленных пакетов;
ожидание их тайм-аутов может продолжаться после сообщения об ошибке одного
работника. Ctrl+C отменяет активные задачи, сохранённые пакеты остаются.
Ожидание `routing.probe_wait` означает занятую пробу восстановления, не повод
вручную переключать на слабую модель. Подробнее —
[политика конкурентности](translation.md#асинхронность-и-общие-ограничения).

## Изменения API после SOLID-рефакторинга

Ошибка `prepare(options) должен вернуть TranslationSession` означает старый
контракт стороннего адаптера. Верните из `prepare` отдельную сессию либо `self`
для stateless-переводчика. При полном совместимом кэше подготовка не требуется.

Предупреждения перевода — `TranslationWarning` с полями `code`, `message`,
`segment_id`; прежние строки доступны через `tuple(map(str, result.warnings))`.
Сам SOLID-рефакторинг CLI не менял. Позднейший strict-контракт Gemini требует
явного legacy-режима для прежних журналов; удалять их или вручную менять
fingerprint не нужно.
Подробнее — [переход API](solid.md#изменения-python-api).

## Технические логи и их ошибки

У конвертации и перевода с `--send` есть JSONL-лог в `logs/`; путь выводится в
stderr. Записи содержат код/категорию, ID, длительность и безопасные метаданные,
не полную строку ошибки. Для диагностики используйте пару `.started/.finished`,
а отсутствие `.finished` после аварии не считайте успешным завершением.

Не удалось открыть лог: выбрать доступный `--log-dir` либо явно `--no-log`;
основная операция ещё не запущена. `logging_unavailable` после открытия означает
отказ записи/сохранения событий; операция продолжилась, а лог может быть неполным.
Не повторяйте перевод вслепую: сначала проверьте существующий журнал прогресса.
Логи могли уйти при ротации/retention. Правила, ограничения и просмотр длительностей
описаны в [руководстве](logging.md). Ошибки argparse до настройки лога — только
в терминале; старые живые запросы без таймингов восстановить полностью нельзя.

## Что не поддерживается надёжно

OCR и веб-интерфейс не входят в цели. Перевод выполняется отдельным необязательным
этапом через Gemini, а не внутри конвертера; ошибки и ограничения этого этапа
описаны в [руководстве по переводу](translation.md). Не восстанавливаются изображения
и текст в них. Произвольная журнальная сетка, три и более колонки, вертикальное
письмо, поток справа налево, математическая структура формул, произвольные сложные/
безлинейные и многостраничные таблицы, многоуровневые списки и автоматическая привязка сносок не имеют общего
решения в этой версии. Начальная настройка ориентирована на английский текст.
Подтверждённые семейства span, двухуровневых шапок и групповых сеток описаны в
[PDF-02](processing.md#структура-таблиц-pdf-02); это ограниченная поддержка, не
универсальное восстановление любой таблицы. Новых флагов CLI нет.
Легенды игровых знаков получают отдельную таблицу при подтверждённом
выравнивании шапки, значений и глифов. При отказе сохраняется обычный текстовый
вывод. Если пары читаются неоднозначно, сверяйте их по исходной странице.

Граница таблицы/рамки, выбор основного размера и выделение абзаца — эвристики,
а не гарантия. Некоторые неподдержанные случаи дают `raw` и предупреждение,
другие могут выглядеть как обычный текст без предупреждения. Вывод «всё хорошо»
нельзя делать только по коду завершения или журналу.

## Что собрать для диагностики

Запишите точную команду или API-вызов, версии Python/pdfplumber, физические страницы,
пути и хеши PDF/MD/TXT, режим и известные решения о дефисах, предупреждения/traceback.
Добавьте небольшой фрагмент ожидаемого и фактического текста, номера строк и
область исходника. Не подменяйте проверяемые файлы новой конвертацией без явного
поручения; сначала установите [проверяемый снимок](quality.md).
