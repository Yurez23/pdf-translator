# SOLID: границы ответственности и переход на новый API

[Документация](README.md) · [Карта файлов](architecture.md) · [Перевод](translation.md)

Рефакторинг выполнен после ревизии текущего проекта, включая логирование.
Сам рефакторинг не менял CLI, эвристики конвертации, промпт, ранжирование моделей,
правила fallback или размер пакетов. Последующее отдельное изменение добавило
fallback для HTTP 503/504 после обычных повторов и короткий кэш недоступности;
оно остаётся внутри политики `model_routing`, не меняя нейтральные порты,
промпт или совместимость журнала. Подробности — в
[политике маршрутизации](translation.md#автовыбор-fallback-и-sqlite).
Асинхронный перевод реализован последующим отдельным изменением. Старые
синхронные порты/API сохранены; CLI использует отдельные async-порты.

## Что было изменено и зачем

| Принцип | Конкретная граница |
| --- | --- |
| SRP | Файловый сценарий перевода собирает зависимости; workflow исполняет пакеты; контроллер управляет попытками; журнал принимает прогресс; файловый store сохраняет JSON. Чтение PDF, предобработка, геометрия и межстраничные продолжения также разделены. |
| OCP | Предупреждения передают явный код, ошибки наследуют общий диагностический контракт. Логирование не разбирает русские фразы и названия классов. Расширение модели событий всё ещё требует явного изменения безопасного allowlist. |
| LSP | Общие проверки подстановки выполняют независимый словарный адаптер, ручной Gemini и auto. Подготовка локальная, набор ID точный, все внешние попытки идут через executor, полный кэш не требует подготовки. |
| ISP | Провайдер содержит identity и подготовку; сессия — только перевод. Контроллер видит только учёт попыток, а не переводы и файловые пути. Нет обязательных SDK-методов, close(), JSON или токенного счётчика у стороннего адаптера. |
| DIP | Workflow не импортирует файловое хранилище или SDK. Политика маршрутизации получает каталог, фабрику модельных сессий и доступность через порты. Gemini/SQLite выбираются в конкретной точке сборки. |

Количество классов само по себе не является критерием. Парсеры, нарезка,
распознавание подписей/заголовков и рендереры сохраняют функциональное устройство.
DI-контейнера, автоматической загрузки плагинов и новых зависимостей нет.

Последующие исправления Introduction не меняют публичные порты: независимые от
PDF SDK локальные правила абзацев вынесены в `paragraphs.py`, геометрическая
привязка маркеров остаётся в `geometry`, классификация графических надписей —
в `headings`. `layout` координирует их. Позднее PDF-01 добавил отдельный адаптер
`pdf_symbols` для PDF/CID и нейтральные `symbols`, `symbol_geometry`,
`symbol_signatures` для смысловых меток и проверенных контуров. Восстановление
идёт до слов/ячеек; экспорт не знает PDF-шрифтов и не заменяет буквы.

Книжный цикл добавил узкие помощники `diagrams.py` и `table_recovery.py`:
они получают нейтральные слова/геометрию, не открывают PDF и не зависят от SDK.
Владение pdfplumber-объектами остаётся в `pdf_reader`; экспорт работает по ролям
и дочерним блокам, не переопределяет структуру по исходным шрифтам. Публичные
восемь экспортов конвертера и переводческие порты не менялись.

## Владение состоянием и ресурсами

- `RunJournal` владеет состоянием прогресса. Его read-only представление переводов
  нельзя изменять снаружи; новый пакет становится принятым после успешной записи.
- `RequestController` получает `AttemptLedger` и `ExecutionPolicy`. Перед каждой
  внешней попыткой журнал сохраняет её резервирование. Сбой записи не запускает
  запрос. История минутной квоты использует wall clock для resume; длительности
  логов — монотонные часы.
- Файловый `CheckpointStore` отвечает за lock/load/save, а не за квоты или смысл
  перевода. Codec проверяет схему и совместимость с планом отдельно от файлов.
- `GeminiProvider.prepare` возвращает сессию с неизменяемыми настройками запуска.
  Повторная подготовка не меняет предыдущую сессию. Фактическая модель приходит
  в результате генерации, не через общее поле `model_version`.
- Auto создаёт отдельную модельную сессию, не меняя приватные поля адаптера.
  Квотная ошибка передаётся router без повтора через отдельное безопасное
  исключение; исходное исключение не изменяется.
- Ресурсами SDK владеет провайдер и вызывающий его код. CLI закрывает провайдер
  через `closing` для sync либо `await aclose()` для async; общий порт сессии
  не требует `close()`.
- Общий механизм вывода подготавливает UTF-8-файлы и публикует их. Правила путей,
  ссылок и перезаписи задаёт сценарий. При overwrite замена атомарна для одного
  файла, но не транзакционна для всей пары.

## Изменения Python API

CLI и сигнатуры `convert_pdf`, `plan_translation`, `translate_file` сохранены.
В корневом `pdf_translator` остаются прежние восемь экспортов.

В `pdf_translator.translation` добавлены `TranslationSession` и
`TranslationWarning`. У порта провайдера изменён результат `prepare(options)`:

```python
from pdf_translator.translation import ProviderIdentity

class DemoProvider:
    identity = ProviderIdentity("demo", "v1")

    def prepare(self, options):
        # Только локальная подготовка. Stateless-адаптер возвращает себя.
        return self

    def translate(self, request, *, executor):
        # Для сетевого адаптера: executor.call(одна_попытка, ...).
        return {item.id: item.text for item in request.items}
```

Состояние старого адаптера, возвращавшего `None`, автоматически не угадывается:
он получает понятную ошибку с предложением обновить контракт. Сложный провайдер
возвращает отдельный объект с методом `translate`; сам провайдер этого метода
иметь не обязан. Конкретный Gemini создаётся/закрывается так же, как раньше.
Его низкоуровневые SDK-методы теперь находятся в отдельном gateway, не на фасаде
`GeminiProvider`.

`TranslationResult.warnings` и `TranslationDocument.warnings` теперь содержат
`TranslationWarning(code, message, segment_id=None)`, а не строки:

```python
# result — результат вашего явно разрешённого запуска.
# for warning in result.warnings:
#     print(warning.code, warning.segment_id, warning.message)
# previous_strings = tuple(map(str, result.warnings))
```

`str(warning)` возвращает прежний текст сообщения; в терминале он не меняется.
Коды: `numbers_changed`, `unchanged_text`, `container_split`, `txt_structure`,
`literal_preserved`, `preview`. Это категории эвристик, не доказательство потери
текста или плохого перевода. У конвертера `ConversionWarning` не менялся.

## Совместимость и проверки

JSON-журнал и контракт плана остаются версии **3**, SQLite — версии **1**,
технические события — версии **1**. Имена сегментов/пакетов, identity/revision,
fingerprint, промпт и политика нарезки сохранены. Миграции или сброса прогресса
нет. Несовместимые старые журналы по-прежнему отклоняются.

Последующее изменение дефолтов ответа до 32768 и локального TPM до 50000
не меняет схемы, но новый ответный бюджет меняет fingerprint. Дорефакторинговые
проверки явно задают прежние 16384: старый журнал совместим при прежних
семантических настройках, а не автоматически при новых дефолтах.

`tests/test_solid_contracts.py` фиксирует дорефакторинговые fingerprint TXT/MD,
проверяет прежний v3-журнал, memory-only workflow, ошибки сохранения, изоляцию
сессий, контракты адаптеров, диагностику и направления импортов. Общие тестовые
хранилища находятся в `tests/support.py`; основная заглушка перевода не наследует
Gemini. SDK проверяется отдельно через MockTransport.

Существующий журнал прежнего живого теста дополнительно прочитан **без записи и
без сети**: его fingerprint совпал, все 250 сохранённых сегментов совместимы.
Это проверка совместимости, не новый живой перевод или независимый PDF-аудит.
Канонические результаты не перегенерировались.

Windows-тест настоящей символьной ссылки по-прежнему может пропускаться при
отсутствии прав; защитная проверка остаётся включённой.

## Последующая асинхронность

`AsyncTranslationProvider.prepare_async` возвращает `AsyncSessionFactory`, создающую
отдельную `AsyncTranslationSession` каждому работнику. Async-порт не навязывает
SDK, JSON, токены или методы управления ресурсами. Sync-реализация порта не
адаптируется скрытно через поток: для async API нужен явный async-адаптер.
Нейтральный workflow зависит от портов, не Gemini; AST-тесты охватывают и новые
модули. Gemini-адаптеры сохраняют общий промпт/декодирование/санитизацию, а сетевые
вызовы async gateway используют SDK `aio`.

`AsyncRequestController` — один на запуск, резервирование и изменение `RunJournal`
происходят без `await` на одном event loop. Это не делает `RunJournal` пригодным
для произвольной записи из потоков. Только каталог (неизменяемый снимок после
single-flight), controller и availability cache намеренно общие; SDK и модельные
сессии изолированы. Здоровые модели не получают эксклюзивных аренд; recovery-probe
арендуется отдельно, busy-probe ожидается. Наблюдатель наследуется через ContextVar.

Файловый preflight/lock/export и валидация/сборка результатов общие между API.
Журнал/план v3, SQLite v1 и семантический fingerprint не меняются из-за
`max_concurrency`; менять его при resume разрешено. Детали остановки, отмены,
лимитов и отсутствие exactly-once — в [руководстве](translation.md#асинхронность-и-общие-ограничения).

## Надёжность ответов после асинхронности

Нейтральный `response_recovery` проверяет результат и ограниченно повторяет
весь пакет. Он не знает SDK, HTTP, файлов или ранжирования, не дробит текст.
Auto вызывает его внутри уже выбранной модельной сессии: ошибка содержимого
не переходит к следующей модели. Отдельное исключение исчерпания предотвращает
повторный внешний цикл. Все внешние попытки по-прежнему идут через executor.

`ResponseValidationError` — исправимое нарушение данных модели, а не любое
`TranslationError`. `BatchFailure` и `TranslationResult.failed_batches` позволяют
явно сообщить incomplete; ошибки ключа, хранения/исходника, безопасности,
MAX_TOKENS и программные ошибки не скрываются в этой категории. `RunJournal`
сохраняет метаданные только после успешной записи; успешный resume снимает
отметки для принятых сегментов.

Журнал v3 расширен необязательным `failed_batches`, без переписывания старых
файлов и без изменения старого кодирования, когда ошибок нет. Строгая объектная
схема Gemini — новая ревизия провайдера, не молчаливая замена прежнего контракта.
Явный `response_contract="legacy"` сохраняет историческую identity, базовый
промпт и массив `id`/`text`; для новых запусков default — strict. Число повторов
ответа — runtime-настройка, не часть семантического fingerprint. Новые
регрессии покрывают оба API и фактический SDK wire format с mock HTTP.
