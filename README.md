# PDF → связный текст для перевода

Локальный конвертер PDF в Markdown и TXT на Python 3.12+. Восстанавливает порядок
чтения в одной/двух колонках, собирает строки в абзацы, сохраняет заголовки, списки,
простые и подтверждённые сложные таблицы, отдельные боковые вставки.
Конвертация PDF не обращается к сети.

Отдельный необязательный этап переводит готовые MD/TXT через Gemini API. Он
отправляет текст Google только при явном `--send`; без этого показывает локальный
план. OCR и веб-интерфейс не входят в цели проекта. Для конвертации нужен PDF
с текстовым слоем.

Пользовательские PDF в `example/` (и старый `example.pdf`), результаты конвертаций
и переводов в `output/`, журналы прогресса и временные артефакты не публикуются
в Git. Эти каталоги исключены через `.gitignore`; локальные файлы сохраняются.

Статус конвертации: проверены содержательные фрагменты 02–17 нового набора
(373 страницы), добавлены регрессии и исправления колонок, абзацев, подписей,
карточек схем и окрашенных таблиц. Это не гарантия идеальной вёрстки:
[остаточные случаи](TODO.md#7-остаточные-случаи-книжной-конвертации) остаются явно перечисленными.

Статус перевода: живая strict/async-проба всей контрольной главы прошла
полностью (250/250 сегментов, 7 минут 17 секунд), включая HTTP-повторы и fallback.
Это не нагрузочная проверка целой книги и не смысловой аудит перевода.
Границы доказанного и ограничения логов — в [контроле качества](docs/quality.md).

Перевод разбивается по подразделам с жёстким капом **16 000 символов**, включая
пробелы. Слишком длинный подраздел делится по абзацам, затем предложениям;
заголовок не отделяется от начала текста. CLI обрабатывает до пяти независимых
пакетов одновременно через асинхронный Gemini SDK; `--max-concurrency 1` оставляет
один активный пакет. Общие ограничения RPM/TPM и бюджета запросов сохраняются.

Ошибки JSON/ID/маркеров повторяются целым пакетом на той же модели (по умолчанию
один повтор), без дробления. Если ответ снова некорректен, остальные пакеты
продолжаются, а запуск заканчивается как неполный (код 4), с сохранённым прогрессом.
Новый strict-формат требует точного набора ID в схеме; для старого журнала нужен
явный `--gemini-response-format legacy --resume`. [Политика надёжности](docs/translation.md#надёжность-ответов-повторы-без-дробления).

CLI конвертации и перевода с `--send` сохраняют технические JSONL-логи в `logs/`:
этапы, длительности, запросы, повторы и предупреждения, без текста книги и ключей.
Другой каталог: `--log-dir PATH`; отключение: `--no-log`. Обычный локальный план
перевода без `--send` остаётся без записи файлов; API подключает логирование явно.

## Установка

Из папки проекта в PowerShell, при установленном Python 3.12 или новее:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
```

На Linux/macOS используйте `python3.12 -m venv .venv`, затем
`.venv/bin/python -m pip install -e .`.

## Конвертация

```powershell
.\.venv\Scripts\python.exe -m pdf_translator "example/2. Introduction.pdf" --output-dir output
.\.venv\Scripts\python.exe -m pdf_translator book.pdf --pages 10-25 --output-dir output
```

После установки также доступна команда `pdf-translator` из окружения.
Если зависимости уже установлены, из корня проекта можно запускать
`python -m pdf_translator ...` без установки самого пакета.

- Без `--pages` обрабатывается весь PDF. Поддерживаются диапазоны и отдельные
  страницы: `--pages 1,3-5`. Нумерация начинается с 1 и соответствует положению
  страницы в файле, а не номеру, напечатанному на странице. Результат всегда идёт
  в исходном порядке; через пропущенные страницы абзацы не склеиваются.
  Для стабильной иерархии заголовков анализируется оформление всего PDF, даже
  при выборе диапазона. Поэтому такой запуск может занимать больше времени,
  чем простое извлечение выбранных страниц. Невыбранный текст не экспортируется,
  не вызывает вопросов о переносах и не добавляет предупреждений.
- Создаются `output/book.md` и `output/book.txt` в UTF-8. Абзацы занимают по одной
  строке и разделяются пустыми строками. В TXT столбцы таблиц разделены табуляцией.
- Существующие результаты сохраняются. Для их замены добавьте `--overwrite`.
  Исходный PDF не перезаписывается.
- При неоднозначном переносе CLI показывает страницу и окружающий текст, затем
  спрашивает: `1` — слить слово, `2` — сохранить дефис, `Q`/Esc — отменить конвертацию.
  В обычном терминале достаточно одного нажатия без Enter. Решение принимается
  отдельно для каждого случая и применяется сразу к обоим выходным форматам.
  До завершения всех ответов файлы результата не записываются.
- Для запуска без вопросов есть `--hyphens keep` (сохранять неоднозначные дефисы)
  и `--hyphens join` (убирать их). По умолчанию действует `--hyphens ask`.
  При перенаправлении stdin можно подавать ответы по одному на строку; окончание
  ввода до ответа завершает команду ошибкой, без молчаливого выбора за пользователя.
- Предупреждения с номерами страниц выводятся в stderr. Код завершения: `0` при
  успешном экспорте (в том числе с предупреждениями), `1` при ошибке файла или
  конвертации, `2` при неверных аргументах команды, `130` при отмене пользователем.

## Python API

```python
from pdf_translator import ConversionError, convert_pdf

try:
    result = convert_pdf("book.pdf", pages="10-25")
except ConversionError as error:
    print(error)
else:
    print(result.markdown)
    print(result.text)
    for warning in result.warnings:
        print(warning.code, warning.pages, warning.message)
    for block in result.blocks:
        print(block.kind, block.text, block.sources)
```

Функция сама не пишет файлы и не обращается к сети; технический sink в API
подключается только явно. `pages` также принимает список
целых номеров страниц. `ConversionResult` содержит оба формата, предупреждения
и упорядоченные блоки. `Block.sources` сохраняет номера страниц и прямоугольники
`(x0, top, x1, bottom)` в PDF-пунктах от левого верхнего угла; у абзаца, продолжающегося
на другой странице, несколько исходных областей. Для таблицы содержимое находится
в `Block.rows`; `Block.text` пуст. Python API позволяет вызывать конвертер из других
локальных программ и скриптов.

У основных заголовков `Block.level` находится в диапазоне 1–6. Названия таблиц
и метки над названием главы сохраняют геометрию заголовка, но имеют `level=0`
и соответственно `role="table_title"` или `role="title_label"`: это не узлы оглавления.

Рамочная вставка — один `Block(kind="aside")`. Её заголовки, абзацы и пункты списков
сохранены в `Block.children`, вместе с их исходными координатами. `Block.text`
остаётся плоским текстом вставки для поиска; экспорт использует дочерние блоки,
поэтому содержимое не дублируется. Заголовок внутри вставки имеет `role="aside_title"`
и не влияет на основное оглавление документа.

Python API по умолчанию не задаёт вопросов: неоднозначные дефисы сохраняются с
предупреждениями. При необходимости передайте `hyphen_resolver`: функцию, которая
получает `HyphenationIssue` с полями `page`, `hyphenated`, `joined`, `context` и
возвращает `True` для склейки или `False` для сохранения дефиса. Например:

```python
result = convert_pdf("book.pdf", hyphen_resolver=lambda issue: True)
```

Обработчик вызывается только для неоднозначных случаев. Заведомые переносы и
составные слова, подтверждённые остальным выбранным текстом, обрабатываются автоматически.

## Что восстанавливается и какие есть ограничения

- Повторяющиеся верхние/нижние колонтитулы и отдельные номера страниц удаляются
  по повторяемости и расположению у края. На коротких документах повторяемость
  может быть недостаточной: в этом случае текст сохраняется.
- Уровни заголовков определяются по стилям всего документа, а не по фиксированным
  размерам шрифта. Близкие размеры объединяются с допуском на погрешности PDF;
  разные шрифты или цвета одинакового размера сами по себе не создают вложенность.
  Названия таблиц и короткие обособленные надписи над крупным названием главы
  сохраняются жирным текстом вне оглавления, если этот стиль не используется
  для обычных разделов. Заголовки рамочных вставок не меняют основную иерархию.
  При более чем шести уровнях глубокие заголовки выводятся как H6 с предупреждением.
  Смысловую вложенность заголовков одинакового размера программа не угадывает.
- Слияние абзацев опирается на геометрию, отступы, шрифты и пунктуацию.
  Явные продолжения между колонками и соседними страницами соединяются.
  Жирное начало само по себе не превращает абзац в список: для пункта без маркера
  нужен висячий отступ продолжения. Кавычка в начале продолжения не мешает склейке;
  заглавная буква допускается при дополнительном признаке — закрытии скобки,
  оставшейся открытой на предыдущей странице/в колонке. Новый абзац с отступом,
  заголовок, таблица и новый пункт списка остаются отдельными блоками. Продолжение
  существующего пункта сохраняет его тип и не получает дополнительный маркер.
- Лигатуры раскрываются, пробелы нормализуются, мягкие переносы удаляются.
  Обычный дефис на границе строк убирается, только если слитное слово встречается
  в выбранном тексте, а вариант с дефисом не встречается. Неоднозначный вариант
  в Python API сохраняется с предупреждением `ambiguous_hyphen`, а в CLI предлагается
  на выбор пользователю. Это правило намеренно осторожное.
- Таблицы распознаются по линиям и окрашенным ячейкам. Подтверждённые span,
  двухуровневые шапки, групповые строки и статистические сетки получают явные
  связи заголовков и значений. Общая ячейка данных выводится один раз под составной
  шапкой; короткие вертикальные метки повторяются только в своих строках.
  Неуверенная структура остаётся отдельным raw-блоком с предупреждением.
  [Правила и пределы PDF-02](docs/processing.md#структура-таблиц-pdf-02).
  Таблицы без подтверждённых границ могут остаться обычным текстом.
- Вставки в распознанных заполненных рамках и сноски выделяются в отдельные блоки.
  Одна рамка экспортируется как одна Markdown-вставка с выделенными заголовками,
  абзацами и списками внутри. Между её абзацами сохраняется цитатная пустая строка
  (`>`), чтобы Markdown не разбивал вставку на несколько отдельных рамок.
  Вставки без рамок и нетипичные сноски могут распознаваться как обычные абзацы.
- Изображения не экспортируются. Короткие подписи к рисункам исключаются до сборки
  абзацев, если они обособлены от основного текста, отличаются оформлением и
  расположены у рисунка. Фоновые изображения страниц не считаются рисунками;
  текст таблиц, их заголовки и рамочные вставки защищены от такого удаления.
  При недостаточных признаках текст сохраняется, поэтому неоднозначные подписи
  и подписи к чисто векторным рисункам могут остаться в результате.
  Короткие вертикальные имена художников мелким шрифтом на внешних полях за
  пределами основных колонок отфильтровываются по совокупности этих признаков.
  Произвольный повёрнутый текст не удаляется: полезные подписи внутри страницы,
  крупные надписи и фрагменты с числами сохраняются.
  OCR, вертикальное письмо и восстановление формул не поддерживаются. Сама
  конвертация не переводит текст; для перевода есть отдельный этап Gemini.
  Поворотный текст сохраняется отдельно с предупреждением `rotated_text`;
  его порядок может потребовать ручной правки.
- Нужен PDF с текстовым слоем. Шифрованные и повреждённые файлы получают понятную
  ошибку. Пустая страница внутри текстового документа пропускается с предупреждением.

Первая версия рассчитана на англоязычные книги с горизонтальным письмом слева
направо. Это эвристический конвертер: сложная журнальная вёрстка, формулы,
трёхколоночные страницы и ошибки кодировки исходного PDF требуют ручной проверки.
Успешное завершение без предупреждений не гарантирует восстановления любой вёрстки.

## Проверка

Установите зависимости для генерации небольших контрольных PDF:

```powershell
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
.\.venv\Scripts\python.exe -m unittest discover -v
```

Тесты создают временные PDF и проверяют порядок колонок, целостность абзацев,
переносы, списки, таблицы, сноски, рамки, выбор страниц, ошибки входа и защиту
от перезаписи. Если есть `example/10. Chapter 8 Goals and Rewards.pdf` (или старый
`example.pdf`), дополнительно проверяются начало
главы, списки, все семь таблиц и склейка `Loyal Cadre` на страницах 10–11. Сам пример
не включён в пакет; без него эти регрессионные проверки пропускаются.

Для `example/2. Introduction.pdf` есть отдельные локальные регрессии заголовков,
абзацев, списков и реплик. Графические надписи больше не определяют уровни
заголовков: они сохраняются отдельно с `graphic_text`. Проверенные игровые
значки получают явные метки вроде `[reaction]` и `[2 actions]` в обоих форматах.
[Нотация, доказательства и пределы](docs/symbols.md) описывают поддержанные шрифты
и векторы; связи схем остаются в [TODO](TODO.md).

Ответственность каждого модуля, тестового и конфигурационного файла, зависимости
и места для диагностики описаны в [карте кодовой базы](docs/architecture.md).

## Перевод через Gemini

Установите extra `translation` (или `dev`, который включает его зависимости):

```powershell
.\.venv\Scripts\python.exe -m pip install -e '.[translation]'
.\.venv\Scripts\python.exe -m pdf_translator.translation output/example.md --limit-units 5
```

Это только план: без ключа, сети, SQLite и новых выходных файлов. По умолчанию
`--model auto`: после разрешения сети список моделей получается из API, выбирается
самое новое поколение и затем класс Pro → Flash → Flash Lite. При модельной квоте,
`404` и сохраняющихся после штатных повторов `503/504` выполняется fallback.
Временные ограничения сохраняются в
`model-availability.sqlite3` в корне проекта, без ключей и текстов; кэш не коммитится.
Явный `--model gemini-...` оставляет ручной режим без fallback.
Ответный бюджет по умолчанию — 32768 токенов, локальный минутный резерв — 50000.
Для старого журнала с бюджетом 16384 при возобновлении задайте его явно;
новый бюджет требует отдельного каталога результата.
Для реального перевода после настройки `GEMINI_API_KEY` добавьте `--send`.
Используйте отдельный проект Google без платного биллинга: программа не может
проверить тариф и не гарантирует бесплатность ключа из платного проекта.
Подробные команды, все параметры и правила возобновления — в
[руководстве по переводу](docs/translation.md).

Переводческое ядро построено по DIP: `TranslationProvider.prepare` возвращает `TranslationSession`, которая принимает сегменты
и возвращает переводы по ID, не навязывая SDK, JSON или токены. Gemini выбирает
только CLI; в Python API адаптер передаётся явно. Для другого переводчика нужен
новый адаптер, а не правки конвейера. Журнал привязан к провайдеру и его ревизии.

Результаты SOLID-рефакторинга, новые типизированные предупреждения и переход
адаптеров на сессии описаны в [руководстве по архитектурным контрактам](docs/solid.md).
